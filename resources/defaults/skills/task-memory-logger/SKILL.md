# Task Memory Logger

## Purpose

每个主要任务完成后，自动写一份 markdown 格式的任务记忆文件，保持跨会话的任务连续性，避免信息丢失。

## When to Use

- 完成一次需求开发
- 完成一个 bug 修复
- 完成一轮重构
- 完成一次调研/分析
- 完成一次部署/发布
- 完成一轮测试
- 任何值得记录的子任务结束时

## Workflow

1. **定位存储目录**：项目根下的 `.yyz/task-memory/`，不存在则创建。
2. **确定文件名**：`YYYY-MM-DD_<short-desc>.md`，简短描述用英文或拼音，避免编码问题。
3. **写内容**：按下方模板填充。
4. **复用策略**：同一个持续任务（如正在开发的 feature）不需要每天新建文件，直接在已有文件中追加或更新 `## 本次完成内容` / `## 下一步计划` 等章节即可。

## Output Template

```markdown
# 任务记忆 - <任务名称>

**日期**: YYYY-MM-DD HH:mm
**会话**: <会话 ID 或简要标识>

## 本次完成内容

- 完成了什么功能/修复了什么
- 涉及哪些文件/模块
- 关键决策和理由

## 下一步计划

- 待办事项 1
- 待办事项 2

## 注意事项

- 已知限制、边界条件
- 潜在风险或坑
- 需要特殊关注的配置/依赖

## 关键数据 (可选)

- 性能数据、接口信息、配置值等
```

## Principles

1. **简洁有效**：每条记录专注关键信息，不要流水账。
2. **面向未来**：写的内容是给将来的自己看的，突出决策原因和风险。
3. **用完即查**：开始新任务前，优先检查 `.yyz/task-memory/` 中是否有相关记录。
4. **不存冗余**：只有未来大概率仍有用、长期稳定的信息才写进去。
